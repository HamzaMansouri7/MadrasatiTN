## 1. Goal and scope

A public section of the platform that shows the generated learning resources of the parascolaire library: for each **class → book → theme**, an infographic, a course deck (8 slides), later a video and a parent article.

| In scope (v1) | Out of scope (v1) |
|---|---|
| Browse by class, book, theme | Login, comments, favourites |
| Show every theme of every book, with its real status | Student accounts (there are none) |
| Infographic viewer, course slide viewer, downloads | Video player (slot reserved, "Bientôt") |
| Real data only for notebook 01 (24 themes) | Server-side rendering of the catalog (see 13) |
| Placeholders for what is not made yet | Editing content in the browser |

The full picture is visible from day one: all 17 books and their themes (about 220) appear, and only what exists is clickable.

## 2. Audience and access

- Parents and teachers. Public read, no login (the public-first rule). No student section.
- FR and AR UI (`lang.tr(fr, ar)`), RTL aware. The resource text itself is Arabic (made in Arabic).

## 4. Content model (the catalog)

One file, `catalog.json`, generated by a tool (section 5), never edited by hand.

```json
{
  "version": 1,
  "generatedAt": "2026-10-12T18:00:00Z",
  "classes": [{ "id": "1ere-annee", "label": "1ère Année", "order": 1 }],
  "books": [{
    "id": "1ere-annee/evaluations-maths-arabe",
    "classe": "1ere-annee",
    "title": "Évaluations 1ère année — Maths & Arabe",
    "number": 1,
    "themeCount": 24,
    "readyCount": 24,
    "resources": { "parentGuide": { "status": "soon" } },
    "themes": [{
      "id": "02-comparaison-et-rangement-des-nombres",
      "n": 2,
      "title": "Comparaison et rangement des nombres",
      "subject": "Mathématiques",
      "exerciseCount": 20,
      "slots": {
        "infographic": { "status": "ready", "orientation": "landscape", "full": "img/…/infographic.3fa9c1d2.webp", "thumb": "img/…/infographic-thumb.3fa9c1d2.webp", "w": 1600, "h": 893 },
        "course":      { "status": "ready", "pages": ["course/…/p1.ab12cd34.webp"], "pdf": "course/…/course.ab12cd34.pdf", "pdfBytes": 3316095 },
        "video":       { "status": "soon" }
      }
    }]
  }]
}
```

**Slot status (computed, never typed):**

| Status | Rule | Shown as |
|---|---|---|
| `ready` | A file exists for the slot | Thumbnail, clickable |
| `in-progress` | No file, but the book has at least one ready slot | "En cours" / "قيد الإعداد" |
| `soon` | No file, and the book has none at all | "Bientôt" / "قريبًا" |

- Per theme: an optional `hidden: true` in the book manifest removes a theme's slot from the public catalog (editorial override). Default is publish everything that exists (owner decision 2026-10-12: publish as it is).
- Which infographic is the public one: the newest approved version; if none approved, the newest version (same rule as `build_progress.py`).
- Theme numbers are **frozen** once published (the file name carries `NN`). The catalog is built from the file names and `manifest.json`, never from a renumbering, so a URL never points to another theme later. Two themes can share a title ("Lettres et sons" is 01 and 05): the number is part of the id.
- Book titles come from `book.json` (rebranded names only; no publisher or original title anywhere).
- Theme titles are shown as stored (French, some Arabic letters). A separate `titleAr` is a later improvement.

## 5. Publish pipeline (new tool)

`parascolaire/tools/publish_catalog.py`, run on the owner's PC. Input: `parascolaire/outputs/**` (masters stay there) and `livres/`. Output: `parascolaire/publish/` (gitignored).

1. Run `dedupe_outputs.py` first (rule: always).
2. For every book/theme in `livres/` (same `analyse()` as the run sheets) read the manifest and pick the files per slot.
3. Images: PNG to **WebP**, max 1600 px, quality 82, plus a 480 px thumbnail. Measured on two real files: 6380 KB PNG to 113 KB, 4548 KB to 67 KB.
4. Course decks: rasterize each PDF page to WebP (1600 px) so the viewer needs no PDF plugin, plus page 1 as thumbnail, plus the original PDF for download.
5. File names get an 8-character content hash (`name.3fa9c1d2.webp`), so files can be cached for a year and a changed file gets a new URL.
6. Write `catalog.json` last, so a half-finished publish never shows broken links.
7. Upload (manual, owner approves each run): `rsync` the `publish/` folder to `/var/madrasati/uploads/parascolaire/` on the VPS. Never deploy or restart anything without the owner's OK.

Naming check built in: a file that does not match the strict name pattern is reported and skipped, never guessed.

## 6. Server (small changes in `src/server.ts`)

| Item | Spec |
|---|---|
| Files | Served from `join(uploadsFolder, 'parascolaire')` (already on the VPS disk and in the nightly backup) under the new path `/media/parascolaire/`. |
| Why not `/uploads/` | That mount sends `Content-Security-Policy: sandbox`, which blocks PDFs in the browser viewer. The new mount keeps `nosniff`, drops `sandbox`, and serves only that folder. |
| Cache | Hashed files: `Cache-Control: public, max-age=31536000, immutable`. |
| Catalog | `GET /api/parascolaire/catalog` reads `catalog.json` from that folder, `Cache-Control: no-cache` + ETag, 404 JSON if missing. Read-only, no auth, no write endpoint. |
| Safety | Static mount with `dotfiles: 'deny'`, `index: false`, `redirect: false` (same as `/uploads`). No directory listing. |
| SEO file | `robots.txt` already disallows `/uploads/`; leave `/media/parascolaire/` allowed so images can be indexed later. |

## 8. UI and design

Owner decision (2026-10-12): the module does not have to follow the DESIGN.md colours or the landing page. The goal is an impeccable, specific design. Process followed: `frontend-design` and `ui-ux-pro-max`, then **Impeccable** (installed 2026-10-12 in `~/.agents/skills/impeccable`): product truth captured in [PRODUCT.md](../PRODUCT.md), direction roll run (`concept-seed`, mode Operate, seed 27046968), direction chosen by the owner, contract saved in `.impeccable/surfaces/src-app-features-parascolaire.md`. Impeccable's Operate rule applies: the world lends only type, palette, density and one signature move; layout, navigation and controls stay standard.

### 8.1 What the skill search proposed, and what was rejected

`ui-ux-pro-max --design-system` returned: Claymorphism, indigo `#4F46E5` with orange `#EA580C`, the "Feature-Rich Showcase" landing pattern, and Noto Naskh Arabic with Noto Sans Arabic. Kept: the Arabic type guidance and the checklist (contrast 4.5:1, visible focus, reduced motion, 375/768/1024/1440 breakpoints, no emoji icons, WebP). Rejected: the style and palette. Indigo plus orange with chunky soft cards is the generic SaaS card kit, it would fight the pastel images, and it says nothing about this subject.

### 8.2 Concept: the school notebook (cahier)

The roll assigned the stamp album (index 7); the owner chose Impeccable's pick, the school notebook. Rejected cards: stamp album, midnight transit map (competitive, dark-first and unreadable at 220 stations on a phone), clean catalogue. Lessons taken from the declined challengers (named raises): from the split-flap board, the grid never reflows when a status changes; from the vertical video feed, the infographic viewer gives one item the whole viewport with a one-flick next theme; from the catalog sleeve, no label is printed twice on a card.

Subject world: a Tunisian primary child's cahier, with its coloured covers per subject, ruled paper, blue ink, pencil and highlighter. Under the Operate rule the module borrows only type, palette, density and one signature move, so the ruled lines stay limited to empty states:

| Notebook object | Used for |
|---|---|
| Seyès ruled lines | Empty states only, never behind images or controls |
| Cover colour per subject | A small subject mark on book and theme cards (table in 8.3) |
| Ink | A resource that exists: solid ink-blue mark |
| Pencil | A resource being prepared: dashed pencil-grey mark |
| Blank line | A resource not made yet: an empty ruled line |
| Highlighter | The coverage ruler: one highlighter stroke per finished theme |

Statuses are ink, pencil and blank line, each with a text label (never colour alone).

### 8.4 Typography

| Role | Latin | Arabic |
|---|---|---|
| Titles and numbers | Lexend 600 (made for reading ease, fits a school audience) | Noto Kufi Arabic 600 (already loaded by the app) |
| Body | Public Sans (already loaded) | Noto Sans Arabic (already loaded) |

Scale (rem): 0.8125 caption, 0.9375 body-s, 1 body, 1.25 card title, 1.75 section title, 2.5 page title. Line height 1.55 body, 1.2 titles, 1.75 for Arabic body. Lines under 56 characters. Sentence case everywhere, no all-caps labels, no letter-spaced eyebrows.

### 8.5 Shape and hierarchy

Different radii for different things, so the page does not read as identical rounded cards: images 4 px, cards 8 px, buttons and inputs 8 px, filter chips full, binder tabs 8 px on the top corners only. Cards are flat: 1 px `rule` border, no shadow at rest; hover moves the border to `ink-blue` (no scale, no lift). 4 px spacing grid, 56 px between sections, 16 px gutters on phones.

### 8.6 Components

| Component | Spec |
|---|---|
| Page header band | Committed shell: full-width `ink` band with white title (Lexend 600, 2.5 rem), one intro sentence, the small seal at the end edge. The coverage ruler fills once on load (the only motion on the page). |
| Class tabs | Standard tabs (role `tablist`), active tab has an `ink-blue` underline and `ink` text, inactive `pencil`. Each shows its book count. Arrow keys move between tabs. |
| Book card | `surface`, 1 px border, title (Lexend 600), subject mark in its cover colour, coverage ruler, "5 sur 24 thèmes" in body-s, one primary button "Ouvrir". Class is not repeated (it is the selected tab). |

| Theme card | 16:9 image box on `sunk` (`object-contain`, portrait images are not cropped), title (Lexend 600, 1.25 rem), subject as plain text, then three slot rows. The whole card is one link. |
| Slot row | A mark plus a label: ink mark and "Infographie" / "Cours" / "Vidéo" when ready; dashed pencil mark and "En cours"; blank line and "Bientôt". Material icons `image`, `slideshow`, `play_circle`. |
| Filters | Two native selects styled to the tokens (subject, status) and a Réinitialiser text button. |

| Image viewer | Full-screen dialog on a dark `#0E1530` scrim, image `object-contain`, close button, Escape. |

### 8.8 States

| State | Behaviour |
|---|---|

### 8.9 Accessibility, motion, responsive

- Contrast AA everywhere (8.3), visible 2 px `ink-blue` focus ring with 2 px offset, every status has a text label, alt text "Infographie: <titre du thème>", dialogs trap and restore focus, tap targets 44 px.
- Motion: one load reveal (ruler fills, 600 ms, ease-out); dialogs open with a 150 ms fade; `prefers-reduced-motion` turns both off. No hover scale, no per-card entrances.
- RTL: logical properties only (`ms-`, `pe-`, `border-s`); binder tabs and the ruler mirror; viewer arrow keys swap.
- Grid: 1 column on phones, 2 from 640 px, 3 from 1024 px, 4 from 1280 px; no horizontal scroll; images `loading="lazy"` with explicit width and height.

## 9. Data flow

```
NotebookLM → outputs/ (masters, manifest.json)
  → publish_catalog.py → publish/ (WebP, hashed names, catalog.json)
  → rsync (owner OK) → VPS /var/madrasati/uploads/parascolaire/
  → Express: /media/parascolaire/* and /api/parascolaire/catalog
  → Angular /parascolaire (loads the catalog, shows cards and viewers)
```

Adding a new output = drop the file in `outputs/`, update the manifest, run the tool, rsync. No code change, the card flips from "Bientôt" to "Disponible".

## 10. Security and rights

- Read-only public endpoints; no upload path for visitors; magic-byte upload rules stay untouched.
- Files are served from one folder only; hashed names; no directory listing.
- Only rebranded names appear (book titles from `livres/`), never source titles or PDFs. `parascolaire_frozen/` and `outputs/` stay out of git.
- The Gemini Notebook watermark stays (accepted).

## 11. Testing

- Unit tests (Vitest) for the pure logic: slot status, best-version pick, catalog selectors, route-to-role matching.
- A catalog validator in `publish_catalog.py` (every referenced file exists, no duplicate ids, counts add up) runs before upload.
- Build, lint and tests run once at the end of each phase. No browser is opened; the owner sends screenshots for the visual check, compared with the DESIGN.md rules.
